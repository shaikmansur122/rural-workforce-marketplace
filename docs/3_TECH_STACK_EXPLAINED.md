## 1. Java & Object-Oriented Programming (OOP)

Java is the language used for the entire backend. The project uses all four pillars of OOP.

---

### 1.1 Encapsulation

**What it is:** Hiding internal data and exposing only what's needed through methods.

**Real example in this project:**

The `User` entity encapsulates all user data. External code cannot directly access fields — it uses getters/setters generated by Lombok's `@Data`:

```java
// User.java
@Entity
@Data  // Generates getters, setters, toString, equals, hashCode
public class User {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false)
    private String name;

    @Column(nullable = false)
    private String password;  // Never exposed directly — always BCrypt hashed

    @Column(precision = 3, scale = 2)
    @Builder.Default
    private BigDecimal rating = BigDecimal.ZERO;
}
```

When `ProfileController` returns user data, it doesn't return the `User` entity directly (which would expose the password). Instead it maps to a `ProfileResponse` DTO:

```java
// ProfileController.java
private ProfileResponse toResponse(User user) {
    return ProfileResponse.builder()
            .id(user.getId())
            .name(user.getName())
            .phone(user.getPhone())
            .role(user.getRole().name())
            .rating(user.getRating())
            // NOTE: password is NOT included — encapsulation protects it
            .build();
}
```

### 1.2 Inheritance

**What it is:** A class inheriting properties and behavior from a parent class.

**Real example in this project:**

`ApiException` extends `RuntimeException`. This means it inherits all exception behavior but adds custom HTTP status:

```java
// ApiException.java
public class ApiException extends RuntimeException {
    private final HttpStatus status;

    public ApiException(HttpStatus status, String message) {
        super(message);  // Calls RuntimeException constructor
        this.status = status;
    }

    public HttpStatus getStatus() { return status; }
}
```

Used throughout the project:
```java
// BookingService.java
if (job.getStatus() != JobStatus.OPEN) {
    throw new ApiException(HttpStatus.UNPROCESSABLE_ENTITY, "Job is not open for booking");
}
```

`GlobalExceptionHandler` catches it and returns the right HTTP response:
```java
@ExceptionHandler(ApiException.class)
public ResponseEntity<String> handleApiException(ApiException ex) {
    return ResponseEntity.status(ex.getStatus()).body(ex.getMessage());
}
```

### 1.3 Polymorphism

**What it is:** One interface, multiple implementations.

**Real example in this project:**

`NotificationService` is an interface. `NotificationServiceImpl` is the implementation. Any class that needs to send notifications depends on the interface, not the concrete class:

```java
// NotificationService.java (interface)
public interface NotificationService {
    void dispatch(Long userId, String message);
}

// NotificationServiceImpl.java (implementation)
@Service
public class NotificationServiceImpl implements NotificationService {
    @Override
    public void dispatch(Long userId, String message) {
        Notification notification = Notification.builder()
                .userId(userId)
                .message(message)
                .isRead(false)
                .build();
        notificationRepository.save(notification);
    }
}
```

`BookingService` uses the interface — it doesn't care about the implementation:
```java
// BookingService.java
public class BookingService {
    private final NotificationService notificationService;  // Interface type

    public BookingResponse createBooking(...) {
        // ...
        notificationService.dispatch(worker.getId(), "You have a new booking request");
    }
}
```

Similarly, `InterestService` interface is implemented by `InterestServiceImpl`.

### 1.4 Abstraction

**What it is:** Hiding complex implementation details, showing only what's necessary.

**Real example in this project:**

`HaversineUtil` abstracts the complex distance calculation formula. The rest of the code just calls `distanceKm()` without knowing the math:

```java
// HaversineUtil.java
public class HaversineUtil {
    private static final double EARTH_RADIUS_KM = 6371.0;

    // Complex math hidden inside — callers don't need to know this
    public static double distanceKm(double lat1, double lon1, double lat2, double lon2) {
        double dLat = Math.toRadians(lat2 - lat1);
        double dLon = Math.toRadians(lon2 - lon1);
        double a = Math.sin(dLat / 2) * Math.sin(dLat / 2)
                + Math.cos(Math.toRadians(lat1)) * Math.cos(Math.toRadians(lat2))
                * Math.sin(dLon / 2) * Math.sin(dLon / 2);
        double c = 2 * Math.atan2(Math.sqrt(a), Math.sqrt(1 - a));
        return EARTH_RADIUS_KM * c;
    }
}

// WorkerService.java — simple clean call
double dist = HaversineUtil.distanceKm(lat, lng, u.getLatitude(), u.getLongitude());
```

### 2.1 Dependency Injection (IoC)

**What it is:** Spring creates and manages objects (beans) and injects them where needed.

**Real example:**

```java
// BookingService.java

    private final BookingRepository bookingRepository;
    private final JobRepository jobRepository;
    private final UserRepository userRepository;
    private final NotificationService notificationService;

    // Spring automatically provides all these when creating BookingService
    public BookingService(BookingRepository bookingRepository,
                          JobRepository jobRepository,
                          UserRepository userRepository,
                          NotificationService notificationService) {
        this.bookingRepository = bookingRepository;
        this.jobRepository = jobRepository;
        this.userRepository = userRepository;
        this.notificationService = notificationService;
    }
}
```

### 2.3 Spring Security + JWT

**What it is:** Security layer that protects endpoints and validates tokens.

**Real example — the JWT filter:**

```java
// JwtAuthFilter.java
@Component
public class JwtAuthFilter extends OncePerRequestFilter {

    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                    HttpServletResponse response,
                                    FilterChain filterChain) {
        // 1. Extract token from Authorization header
        String authHeader = request.getHeader("Authorization");
        if (authHeader == null || !authHeader.startsWith("Bearer ")) {
            filterChain.doFilter(request, response);
            return;
        }

        String token = authHeader.substring(7);

        // 2. Validate token and extract user ID
        Long userId = jwtUtil.extractUserId(token);

        // 3. Set authentication in Spring Security context
        UsernamePasswordAuthenticationToken auth =
            new UsernamePasswordAuthenticationToken(userId, null, authorities);
        SecurityContextHolder.getContext().setAuthentication(auth);

        filterChain.doFilter(request, response);
    }
}
```

## 3. MySQL & SQL

MySQL stores all the application data. SQL is used for queries, schema creation, and data management.

---

### 3.1 Schema Design

**Real example — the jobs table:**

```sql
-- schema.sql
CREATE TABLE jobs (
    id          BIGINT AUTO_INCREMENT PRIMARY KEY,
    provider_id BIGINT NOT NULL,
    skill       VARCHAR(100) NOT NULL,
    date        DATE NOT NULL,
    time_slot   VARCHAR(20) NOT NULL,
    location    VARCHAR(255) NOT NULL,
    wage        DECIMAL(10,2) NOT NULL,
    status      ENUM('OPEN','PENDING','BOOKED','COMPLETED') DEFAULT 'OPEN',
    latitude    DOUBLE,
    longitude   DOUBLE,
    FOREIGN KEY (provider_id) REFERENCES users(id)
);
```

The `FOREIGN KEY` creates a relationship — every job must belong to a valid user (provider).

### 4.3 Context API — Global State

**Real example — AuthContext:**

```javascript
// AuthContext.js
const AuthContext = createContext();

export function AuthProvider({ children }) {
  const [user, setUser] = useState(null);
  const [token, setToken] = useState(localStorage.getItem('token'));

  const login = (userData, jwtToken) => {
    setUser(userData);
    setToken(jwtToken);
    localStorage.setItem('token', jwtToken);
  };

  const logout = () => {
    setUser(null);
    setToken(null);
    localStorage.removeItem('token');
  };

  return (
    <AuthContext.Provider value={{ user, token, login, logout }}>
      {children}
    </AuthContext.Provider>
  );
}

// Used in any component:
```

### 4.4 useCallback — Preventing Unnecessary Re-renders

**Real example:**

```javascript
// WorkerDashboard.js
const fetchJobs = useCallback(async (p = 0) => {
  setJobsLoading(true);
  try {
    const res = await api.get(`/jobs?page=${p}&size=20`);
    setJobs(res.data.content ?? res.data);
  } finally {
    setJobsLoading(false);
  }
}, []);  // Empty deps = function never recreated
```

Without `useCallback`, `fetchJobs` would be a new function on every render, causing infinite loops in `useEffect`.

## 10. JWT (JSON Web Tokens)

JWT is used for stateless authentication — no sessions stored on the server.

---

### 10.1 Token Structure

A JWT has 3 parts separated by dots:
```
eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiIzIiwicm9sZSI6IldPUktFUiIsImlhdCI6MTcxNjI5NDA2NSwiZXhwIjoxNzE2MzgwNDY1fQ.signature
     HEADER                                    PAYLOAD                                                    SIGNATURE
```

The payload contains:
```json
{
  "sub": "3",          // User ID
  "role": "WORKER",    // User role
  "iat": 1716294065,   // Issued at
  "exp": 1716380465    // Expires at (24 hours later)
}
```

### 10.2 Token Generation

**Real example:**

```java
public String generateToken(Long userId, String role) {
    return Jwts.builder()

            .claim("role", role)
            .setIssuedAt(new Date())
            .setExpiration(new Date(System.currentTimeMillis() + expirationMs))
            .signWith(getSigningKey(), SignatureAlgorithm.HS256)

}
```

## 11. BCrypt Password Hashing

BCrypt is a one-way hashing algorithm for passwords. You can never reverse it to get the original password.

---

### 11.1 How It Works in This Project

**Registration:**
```java
// AuthService.java
String hashedPassword = passwordEncoder.encode(request.getPassword());
// "password123" → "$2a$12$c0r9C/g/Nlz6IUcjXaN18.zOOwGA98q3x79ikzERuTuGnh1NcyZp2"
user.setPassword(hashedPassword);
```

**Login:**
```java
// AuthService.java
if (!passwordEncoder.matches(request.getPassword(), user.getPassword())) {
    throw new ApiException(HttpStatus.UNAUTHORIZED, "Invalid credentials");
}
// passwordEncoder.matches("password123", "$2a$12$c0r9...") → true
```

The `$2a$12$` prefix means: BCrypt algorithm, cost factor 12 (2^12 = 4096 iterations). Higher cost = harder to brute-force.
